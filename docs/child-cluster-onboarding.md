# Child Cluster Onboarding

This guide covers how to define a new bare metal OpenShift cluster, register it with the ACM Hub, and have it managed via GitOps.

ACM uses the Assisted Installer service (part of MultiClusterEngine) to provision bare metal clusters. The same Agent-Based Installer mechanics used for the hub apply to child clusters — each node boots from a cluster-specific agent ISO that is generated by the Assisted Installer service running on the hub (rather than by the `openshift-install` CLI).

## 1. How Child Cluster Provisioning Works

```
                Git Commit (new cluster definition)
                        │
                        ▼
             ArgoCD (hub) detects change
                        │
                        ▼
         ClusterDeployment + InfrastructureEnv
         applied to open-cluster-management-hub ns
                        │
                        ▼
         Assisted Installer (on hub) generates
         cluster-specific agent ISO
                        │
                        ▼
    BMC mounts ISO → nodes boot → cluster installs
                        │
                        ▼
         ACM imports cluster, applies
         gitops-bootstrap-policy
                        │
                        ▼
         Child cluster ArgoCD pulls its own
         Application manifests from Git
```

### Key resources

| Resource | API Group | Purpose |
|----------|-----------|---------|
| `ClusterDeployment` | `hive.openshift.io/v1` | Cluster identity, pull secret reference, install strategy |
| `InfrastructureEnv` | `agent-install.openshift.io/v1beta1` | Links to ClusterDeployment; triggers ISO generation |
| `NMStateConfig` | `agent-install.openshift.io/v1beta1` | Per-node static network config (IP, gateway, DNS, routes) |
| `AgentCluster` | `capi-provider.agent-install.openshift.io/v1alpha1` | Cluster API binding (optional, for CAPI workflows) |
| `ManagedCluster` | `cluster.open-cluster-management.io/v1` | ACM cluster registration |
| `KlusterletAddonConfig` | `agent.open-cluster-management.io/v1` | ACM addon configuration per cluster |

## 2. Prerequisites

- Hub cluster is fully running with ACM, Vault, and ESO healthy
- `AgentServiceConfig` in `components/acm-configuration/` is deployed and the assisted-service pod is Running
- `ClusterImageSet` for the target OCP version exists (see `components/acm-configuration/clusterimageset.yaml`)
- Nodes have iDRAC/BMC reachable from the hub cluster (for Redfish virtual media operations) **or** from the Ansible control node
- DNS entries for the new cluster are in place: `api.<cluster>.<domain>` and `*.apps.<cluster>.<domain>`

## 3. Plan the Cluster

Document the following before creating any files:

| Setting | Example | Notes |
|---------|---------|-------|
| Cluster name | `spoke1` | Short, DNS-safe, unique |
| Base domain | `example.com` | Must match hub or a delegated zone |
| OCP version | `4.21` | Must match an available ClusterImageSet |
| Node count | 3 (compact) or 3+N | 3 masters; add workers for larger |
| Rendezvous IP | `192.168.2.10` | One control plane node IP |
| Machine network | `192.168.2.0/24` | Physical node subnet |
| Cluster network | `10.132.0.0/14` | Must not overlap with hub or other clusters |
| Service network | `172.31.0.0/16` | Must not overlap with hub or other clusters |
| MetalLB pool | `192.168.2.200–220` | Reserved for LoadBalancer services |
| Git branch | `main` | Branch ArgoCD tracks for this cluster |

> **Network isolation:** Each cluster's `cluster_network_cidr` and `service_network_cidr` must be unique across all clusters. Use non-overlapping ranges even if clusters are on separate L2 segments — ACM routing can bridge them.

## 4. Register the Cluster in Git

### 4a. Add to cluster-versions.yaml

`clusters/cluster-versions.yaml` maps each cluster name to the git branch it tracks. Add your new cluster:

```yaml
data:
  hub: main
  spoke1: main   # add this line
```

Commit and push this change — ArgoCD on the hub will pick it up and expect a `clusters/spoke1/` directory to exist.

### 4b. Create the cluster directory

```
clusters/
└── spoke1/
    ├── kustomization.yaml          # Kustomize entry point
    ├── values.yaml                 # spoke1-specific ArgoCD applications
    ├── clusterdeployment.yaml      # Hive: cluster identity + install config
    ├── infraenv.yaml               # MCE: ISO generation + node discovery
    └── nodes/
        ├── hub-node1-nmstate.yaml  # NMStateConfig per node
        ├── hub-node2-nmstate.yaml
        └── hub-node3-nmstate.yaml
```

### 4c. Create kustomization.yaml

```yaml
# clusters/spoke1/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - ../cluster-versions.yaml
  - clusterdeployment.yaml
  - infraenv.yaml
  - nodes/

generators:
  - |-
    apiVersion: builtin
    kind: HelmChartInflationGenerator
    metadata:
      name: spoke1-apps
    chartHome: ../../.helm-charts
    chartName: argocd-app-of-app
    releaseName: spoke1
    valuesFile: values.yaml
    additionalValuesFiles:
      - ../../groups/all/values.yaml
    includeCRDs: false

replacements:
  - source:
      kind: ConfigMap
      name: cluster-versions
      fieldPath: data.spoke1
    targets:
      - select:
          kind: Application
        fieldPaths:
          - spec.source.targetRevision
```

### 4d. Create ClusterDeployment

```yaml
# clusters/spoke1/clusterdeployment.yaml
---
apiVersion: v1
kind: Namespace
metadata:
  name: spoke1
---
apiVersion: hive.openshift.io/v1
kind: ClusterDeployment
metadata:
  name: spoke1
  namespace: spoke1
spec:
  baseDomain: example.com
  clusterName: spoke1
  controlPlaneConfig:
    servingCertificates: {}
  installed: false
  clusterInstallRef:
    group: extensions.hive.openshift.io
    version: v1beta1
    kind: AgentClusterInstall
    name: spoke1
  platform:
    agentBareMetal:
      agentSelector:
        matchLabels:
          cluster-name: spoke1
  pullSecretRef:
    name: spoke1-pull-secret      # ExternalSecret created in Section 6
```

```yaml
# clusters/spoke1/agentclusterinstall.yaml  (add to resources in kustomization.yaml)
---
apiVersion: extensions.hive.openshift.io/v1beta1
kind: AgentClusterInstall
metadata:
  name: spoke1
  namespace: spoke1
spec:
  clusterDeploymentRef:
    name: spoke1
  imageSetRef:
    name: openshift-4.21
  networking:
    clusterNetwork:
      - cidr: 10.132.0.0/14
        hostPrefix: 23
    serviceNetwork:
      - 172.31.0.0/16
    machineNetwork:
      - cidr: 192.168.2.0/24
  provisionRequirements:
    controlPlaneAgents: 3
    workerAgents: 0
  sshPublicKey: ""              # populated by ExternalSecret or literal value
```

### 4e. Create InfrastructureEnv

```yaml
# clusters/spoke1/infraenv.yaml
---
apiVersion: agent-install.openshift.io/v1beta1
kind: InfrastructureEnv
metadata:
  name: spoke1
  namespace: spoke1
spec:
  clusterRef:
    name: spoke1
    namespace: spoke1
  sshAuthorizedKey: ""          # populated by ExternalSecret or literal value
  pullSecretRef:
    name: spoke1-pull-secret
  nmStateConfigLabelSelector:
    matchLabels:
      cluster-name: spoke1
  # cpuArchitecture defaults to x86_64
```

## 5. Define Nodes

Each node needs an `NMStateConfig` resource that declares its static network configuration. The Assisted Installer embeds these into the generated ISO so nodes come up with the right IP at boot.

### Template: `clusters/spoke1/nodes/node1-nmstate.yaml`

```yaml
---
apiVersion: agent-install.openshift.io/v1beta1
kind: NMStateConfig
metadata:
  name: spoke1-node1
  namespace: spoke1
  labels:
    cluster-name: spoke1        # must match infraenv.nmStateConfigLabelSelector
spec:
  # macAddress ties this NMStateConfig to the specific NIC on this node.
  # The Assisted Installer matches the ISO boot config to the node by MAC.
  interfaces:
    - name: eno1
      macAddress: "aa:bb:cc:dd:ee:10"

  # nmstate network configuration (same format as agent-config.yaml.j2)
  config:
    interfaces:
      - name: eno1
        type: ethernet
        state: up
        ipv4:
          enabled: true
          dhcp: false
          address:
            - ip: 192.168.2.10
              prefix-length: 24
    dns-resolver:
      config:
        server:
          - 192.168.2.1
    routes:
      config:
        - destination: 0.0.0.0/0
          next-hop-address: 192.168.2.1
          next-hop-interface: eno1
```

Create one file per node, incrementing the IP and MAC. For a 3-node compact cluster:

| File | Node name | IP | MAC |
|------|-----------|-----|-----|
| `node1-nmstate.yaml` | `spoke1-node1` | `192.168.2.10` | `aa:bb:cc:dd:ee:10` |
| `node2-nmstate.yaml` | `spoke1-node2` | `192.168.2.11` | `aa:bb:cc:dd:ee:11` |
| `node3-nmstate.yaml` | `spoke1-node3` | `192.168.2.12` | `aa:bb:cc:dd:ee:12` |

Add a `kustomization.yaml` inside `nodes/`:

```yaml
# clusters/spoke1/nodes/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - node1-nmstate.yaml
  - node2-nmstate.yaml
  - node3-nmstate.yaml
```

## 6. Load Cluster Secrets into Vault

Child cluster secrets (pull secret, SSH key) live in Vault at `secret/<cluster-fqdn>/` and are surfaced via ExternalSecrets. Add them to `ansible/values-secret.yaml` and re-run the vault load task, **or** push them directly with the Vault CLI.

### Add to `ansible/values-secret.yaml`

```yaml
spoke1_pull_secret:
  vault_path: "secret/spoke1.example.com/pull-secret"
  fields:
    pullSecret: '<full pull secret JSON>'

spoke1_ssh_key:
  vault_path: "secret/spoke1.example.com/ssh-keys"
  fields:
    publicKey: "ssh-rsa AAAA..."
```

Then reload:

```bash
cd ansible
ansible-playbook playbooks/acm_hub_configure.yml \
  --tags vault_load \
  --ask-vault-pass
```

### Create ExternalSecret resources in Git

```yaml
# clusters/spoke1/externalsecret-pull-secret.yaml
---
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: spoke1-pull-secret
  namespace: spoke1
spec:
  refreshInterval: 1h
  secretStoreRef:
    kind: ClusterSecretStore
    name: vault-backend
  target:
    name: spoke1-pull-secret
    template:
      type: kubernetes.io/dockerconfigjson
      data:
        .dockerconfigjson: "{{ .pullSecret }}"
  dataFrom:
    - extract:
        key: secret/spoke1.example.com/pull-secret
```

Add this file to `resources:` in `clusters/spoke1/kustomization.yaml`.

## 7. Boot the Nodes

Once the resources are committed and ArgoCD has synced them to the hub, the Assisted Installer generates the discovery ISO automatically. Retrieve the ISO URL from the `InfrastructureEnv` status:

```bash
oc get infraenv spoke1 -n spoke1 \
  -o jsonpath='{.status.isoDownloadURL}'
```

### Mount the ISO via Ansible

If you have Ansible automation for the spoke BMCs, use the same `bmc_virtual_media.yml` and `bmc_power_control.yml` tasks used for the hub. Create a minimal inventory for the spoke nodes:

```yaml
# ansible/inventory/spoke1_nodes.yml
all:
  hosts:
    spoke1-node1:
      ansible_host: "192.168.2.10"
      idrac_ip: "192.168.0.21"
      idrac_user: "{{ vault_idrac_user_spoke1_node1 }}"
      idrac_password: "{{ vault_idrac_password_spoke1_node1 }}"
      iso_url: "https://assisted-service.hub.example.com/byid/..."
```

```bash
ansible-playbook playbooks/bare_metal_prep.yml \
  -i inventory/spoke1_nodes.yml \
  --ask-vault-pass
```

### Mount the ISO manually

Alternatively, paste the ISO URL directly into each node's iDRAC virtual media console:

1. Log in to iDRAC → **Configuration → Virtual Media**
2. Select **Connect Virtual Media** → **Map CD/DVD**
3. Enter the ISO URL from `InfrastructureEnv.status.isoDownloadURL`
4. Reboot the node and set one-time boot from virtual CD

## 8. Monitor Provisioning

Watch agents register as nodes boot:

```bash
# Agents appear as nodes boot from the ISO
watch oc get agents -n spoke1

# When all agents show Approved/Bound, installation begins
oc get agentclusterinstall spoke1 -n spoke1 -o yaml | grep -A5 conditions

# Progress events
oc get events -n spoke1 --sort-by='.lastTimestamp' | tail -20
```

Full installation takes 45–90 minutes depending on hardware.

## 9. Verify the Managed Cluster

```bash
# Cluster appears in ACM
oc get managedcluster spoke1

# Retrieve the kubeconfig
oc get secret spoke1-admin-kubeconfig -n spoke1 \
  -o jsonpath='{.data.kubeconfig}' | base64 -d > /tmp/spoke1.kubeconfig

# Verify cluster nodes
KUBECONFIG=/tmp/spoke1.kubeconfig oc get nodes

# Verify cluster operators
KUBECONFIG=/tmp/spoke1.kubeconfig oc get clusteroperators
```

## 10. GitOps for the Child Cluster

The `gitops-bootstrap-policy` (wave 15 on the hub) installs the OpenShift GitOps operator on every managed cluster automatically once ACM marks it Available.

Once the GitOps operator is running on the spoke, you can deploy workloads to it through either:

### Option A — Centralized (hub ArgoCD pushes to spoke)

Add the spoke as a destination in the hub ArgoCD and create Applications that target it:

```yaml
# In clusters/hub/values.yaml — an Application that deploys to the spoke
applications:
  spoke1-workloads:
    path: workloads/spoke1
    syncWave: "25"
    destination:
      server: https://api.spoke1.example.com:6443
      namespace: default
```

The spoke cluster must be registered as a destination in ArgoCD:

```bash
# ArgoCD CLI — register spoke as a cluster destination
argocd cluster add spoke1 --kubeconfig /tmp/spoke1.kubeconfig
```

### Option B — Decentralized (spoke ArgoCD pulls independently)

Create a `clusters/spoke1/values.yaml` with the spoke-specific applications. The spoke's own ArgoCD instance (deployed by the bootstrap policy) points at this Git repository and pulls its own manifests. This is the decentralized model where each cluster is self-sufficient after bootstrapping.

```yaml
# clusters/spoke1/values.yaml
applications:
  spoke1-operators:
    path: workloads/spoke1/operators
    syncWave: "5"
    destination:
      namespace: openshift-operators
```

The spoke ArgoCD root application should point at `clusters/spoke1` in this repository, using the branch pinned in `clusters/cluster-versions.yaml`.

## Adding More Clusters

Repeat this process for each additional cluster. The pattern scales horizontally:

1. Add `<cluster-name>: <branch>` to `clusters/cluster-versions.yaml`
2. Create `clusters/<cluster-name>/` with `kustomization.yaml`, `values.yaml`, `clusterdeployment.yaml`, `infraenv.yaml`, and the `nodes/` NMStateConfig files
3. Add cluster secrets to Vault
4. Commit, push — ArgoCD on the hub picks up the changes and triggers Assisted Installer provisioning
5. Mount ISOs (manually or via Ansible) and boot the nodes
